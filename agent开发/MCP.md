1. **LLM应用进程**（也就是你说的"客户端"）—— 发起请求的一方
    
2. **外部服务进程**（也就是你说的"服务端"）—— 提供工具的一方
    
### 代码组织层面（只是工程内的模块划分）：

- **Host逻辑**：你的业务代码（"什么时候调什么工具"）
    
- **Client逻辑**：MCP SDK提供的网络通信封装（"怎么发请求、怎么收响应"）
    
- **Protocol逻辑**：MCP SDK提供的消息格式规范（"JSON-RPC怎么拼"）

## MCP 的工作原理

MCP 通过定义标准化的数据格式和通信协议，实现 LLM 与外部资源的交互。

MCP 使用 JSON-RPC 2.0 作为消息格式，通过标准的请求、响应和通知消息进行通信。

MCP 支持多种传输机制，包括本地的标准输入/输出（Stdio）和基于HTTP的服务器发送事件（SSE）。

MCP的生命周期包括初始化、运行和关闭三个阶段，确保连接的建立、通信和终止都符合协议规范。
